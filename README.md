**Web & Game Engineer** is a modular, cross-platform AI engineering framework for building modern websites, 2D games, 3D games, interactive workbenches and real-time simulation systems. It brings a shared engineering methodology, specialized workflows and platform-specific adapters to six AI ecosystems—without pretending that every host has the same tools or capabilities.

**Web & Game Engineer** 是一套模块化、跨 AI 平台的工程开发体系，面向现代网站、2D 游戏、3D 游戏、交互式工作台与实时仿真系统。它以统一工程核心、专业化开发流程和独立平台适配器连接六大 AI 生态，同时尊重不同宿主真实存在的工具与能力边界。

> **One shared engineering standard. Independent platform integrations. Verifiable delivery.**  
> **统一工程标准，独立平台集成，交付结果可验证。**

## Engineering capabilities / 工程能力

### Nine professional modules / 九大专业模块

| # | Module | Scope / 能力范围 |
|---:|---|---|
| 01 | **Web Development** | HTML5, CSS, JS/TS, responsive UI, routing, state, browser storage and accessibility. / 网页结构、响应式界面、状态管理、路由、存储与无障碍。 |
| 02 | **2D Game Development** | Canvas/WebGL, game loops, input, animation, collision, maps, levels and saves. / 游戏循环、输入、动画、碰撞、地图关卡与存档。 |
| 03 | **3D Game Development** | Three.js scenes, terrain, cameras, lighting, materials, models, world chunks and resource lifecycle. / 三维场景、地形、相机、光照、材质、模型与资源生命周期。 |
| 04 | **3D Workbench** | Scene/object editing, transforms, inspectors, terrain tools, asset management and export. / 场景与物体编辑、变换、属性检查器、地形工具、资产管理与导出。 |
| 05 | **Physics Engine** | Physics core, vehicle and character motion, environment interaction and destruction systems. / 物理核心、载具与角色运动、环境交互及破坏系统。 |
| 06 | **Animation System** | Skeletons, keyframes, state machines, blending, inverse kinematics and events. / 骨骼、关键帧、状态机、混合、逆向运动学与动画事件。 |
| 07 | **AI Game Logic** | NPC state machines, behavior trees, pathfinding, perception, dialogue and quests. / NPC 状态机、行为树、寻路、感知、对话与任务逻辑。 |
| 08 | **Testing & Repair** | Unit, integration, interaction, visual, performance and regression tests with bounded repair. / 单元、集成、交互、视觉、性能、回归测试与有限次修复。 |
| 09 | **Deployment & Git** | Build, packaging, version control, GitHub workflows, deployment and delivery. / 构建、打包、版本管理、GitHub 工作流、部署与交付。 |

Modules are enabled by default but loaded only when relevant. A simple website does not need a 3D engine; a 2D game should not inherit an unnecessary 3D physics stack.

模块默认启用，但只在任务需要时加载。简单网站不必引入 3D 引擎，2D 游戏也不应被迫承担无关的 3D 物理依赖。

### Seven virtual engineering roles / 七大虚拟专业角色

1. **Project Manager / Game Director — 项目经理 / 游戏总监:** requirements, scope, priorities and acceptance criteria. / 需求、范围、优先级与验收标准。
2. **System Architect — 系统架构师:** boundaries, data flow, interfaces and technical decisions. / 系统边界、数据流、接口与技术决策。
3. **Web Engineer — Web 工程师:** browser applications, UI, interaction and integration. / 浏览器应用、界面、交互与集成。
4. **Game Engineer — 游戏工程师:** gameplay systems, controls, scenes and game state. / 玩法系统、控制、场景与游戏状态。
5. **Physics Engineer — 物理工程师:** movement, collision, forces, stability and simulation. / 运动、碰撞、受力、稳定性与仿真。
6. **Technical Artist — 技术美术:** assets, materials, lighting, animation and performance budgets. / 资产、材质、光照、动画与性能预算。
7. **QA Engineer — 测试工程师:** test design, regression, defect triage and delivery verification. / 测试设计、回归、缺陷分级与交付验证。

These are structured role perspectives, not a claim that seven independent AI agents are running. If a host does not provide multi-agent execution, the roles are performed sequentially.

以上是结构化的专业职责视角，并不意味着系统正在运行七个独立 AI Agent。如果宿主不支持多智能体执行，这些职责将按流程依次完成。

## A disciplined engineering workflow / 标准工程工作流

`Requirements → Inspection → Architecture → Plan → Build → Test → Repair → Optimize → Deliver`

`需求分析 → 项目检查 → 架构设计 → 任务规划 → 增量开发 → 自动测试 → 有限修复 → 性能优化 → 完整交付`

- **Inspect before changing:** understand existing entry points, dependencies, assets, state and tests. / **先检查再修改：** 理解现有入口、依赖、资源、状态与测试。
- **Protect existing work:** prefer scoped changes, preserve behavior and regression-test affected flows. / **保护既有项目：** 优先局部修改，保留原有行为并执行回归测试。
- **Repair with limits:** cap repeated attempts against the same root cause and stop when evidence is insufficient. / **修复有边界：** 对同一根因限制重试次数，证据不足时停止并报告。
- **Optimize by evidence:** prioritize correctness and stability before visual fidelity or feature count. / **以证据优化：** 正确性与稳定性优先于画面堆叠和功能数量。
- **Deliver reproducibly:** include source, instructions, test status, known issues and version information. / **交付可复现：** 提供源文件、说明、测试状态、已知问题与版本信息。

## Cross-platform strategy / 跨平台策略

The project uses one shared Core with independent adapters. Each adapter describes its own host-specific installation route, capabilities, limitations and verification status.

项目采用统一 Core + 独立平台 Adapter 的结构。每个适配器分别描述宿主安装方式、能力、限制和验证状态。

| Platform | Adapter route / 适配路线 | Current status / 当前状态 |
|---|---|---|
| ChatGPT | Portable instruction package and ChatGPT-specific workflow. / 可移植指令包与 ChatGPT 工作流。 | Experimental · Not Certified |
| Claude | Claude.ai Skill and Claude Code plugin are separate targets. / Claude.ai Skill 与 Claude Code 插件分开适配。 | Experimental · Not Certified |
| Gemini | Gemini Apps Skill adapter. / Gemini Apps Skill 适配器。 | Experimental · Not Certified |
| DeepSeek | Portable chat prompt and API system/instructions adapter. / 对话提示词与 API 指令适配。 | Experimental · Not Certified |
| Qwen | Qwen Code and Model Studio Agent Skills have separate packages. / Qwen Code 与 Model Studio Agent Skills 分别打包。 | Experimental · Not Certified |
| Doubao | Portable chat prompt and Volcengine Ark API adapter. / 对话提示词与火山引擎 Ark API 适配。 | Experimental · Not Certified |

**Certification is independent.** A successful ZIP build proves archive integrity only. It does not prove native import, host permissions, runtime behavior or full workflow compatibility. No platform is currently marked as formally certified.

**认证相互独立。** ZIP 打包成功仅代表压缩包完整，不代表原生导入、宿主权限、运行行为或完整工作流兼容。当前没有任何平台被标记为正式认证通过。

See the [Acceptance Matrix](release/acceptance-matrix.csv) for the latest test and certification record.

## Security, approvals & quality / 安全、审批与质量

- Never place API keys, tokens or passwords in source code, logs or ZIP archives. / 不得将 API Key、令牌或密码写入源码、日志或 ZIP。
- Treat external content and generated code as untrusted until reviewed and tested. / 外部内容与生成代码在审查测试前均视为不可信。
- Require explicit approval for destructive changes, migrations, breaking interfaces, remote publication, deployment, external uploads and paid operations. / 删除覆盖、迁移、破坏性接口变更、远程发布、部署、外部上传及付费操作必须明确审批。
- Report test states honestly: `PASS`, `FAIL`, `PARTIAL`, `NOT RUN` or `MANUAL`. / 如实报告测试状态，不把静态审查说成真实运行测试。
- Keep known limitations visible; do not infer certification from a package build. / 明确展示已知限制，不以打包成功推断平台认证。
